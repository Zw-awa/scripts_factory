# Scripts Factory 本地中枢架构

## 边界

本系统通过任务经验、分层记忆和可复用 skill 积累能力，不训练或修改模型权重。CLI 直接调用核心库，不包含常驻后台服务。

## 数据流

1. 路由器按规则评估目标，边界任务由 provider 复核。
2. 简单任务创建单节点；复杂任务由策划 session 生成有向无环任务图。
3. 调度器检查能力和路径审批，在并发、节点数和超时限制内执行 session。
4. 每个状态变化写入 SQLite 事件与检查点；中断任务只能由用户显式恢复。
5. 成功任务形成候选记忆；`sleep` 负责晋升、归档和生成 skill 候选。
6. skill 候选通过元数据校验和自检后仍需用户确认，发布时刷新正式 bundle 索引。

## 记忆层次

- 短期：session 输入输出和事件日志。
- 中期：任务、任务图、检查点和任务总结。
- 长期：确认后的事实、偏好、工作流与正式 skill。
- 用户画像：行为模式可形成候选；敏感属性必须由用户明确确认。

## 安全模型

读取和自检属于低风险能力。文件写入、删除、联网和发布必须匹配已有的“能力 + 资源路径”审批。所有修改状态的 CLI 命令提供 `--dry-run`；OpenCode 适配器不会传递全局自动批准参数。

## Provider

- `fake`：确定性测试和本地演示。
- `opencode`：通过 `opencode run --format json` 执行和恢复外部 session。
- `openai`：通过 Responses API 执行，凭据仅从 `OPENAI_API_KEY` 读取。

Provider 异常、超时和非零退出都会转换为持久化失败状态，不会跳过审计日志。
